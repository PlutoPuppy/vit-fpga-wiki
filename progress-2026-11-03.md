# Implementation progress — 2026-11-03

This update records Winnie's softmax/GELU work and Jerry's matmul progress. Status is based on the source and recorded validation below; no new FPGA build or board run was performed for this documentation update.

## Winnie — GELU and bias

Implemented an exact erf-based Python GELU reference, a 256-entry signed int8 LUT, ready/valid GELU RTL, and a same-scale bias/GELU wrapper. Bias addition uses signed 9-bit arithmetic and saturation before the LUT. The documented test suite covers all 256 GELU inputs, all 65,536 bias/input pairs, stalls and reset.

The matmul integration prototype instantiates a readout module in `accel_top.sv`: 16 parallel int8 lanes on the 128-bit output read path, a 256-byte per-row bias buffer, and optional bypass. GELU runs only when the host reads completed matmul output; it does not alter intermediate accumulation or write activated values back to RAM. The mocked synchronous-RAM readout test covers 1,024 bytes, bias writes, bypass and reset.

The current contract requires matching matmul, bias and LUT input scales; the example input/output scales of 1/32 are demonstration values. Enabled readout requires output width M to be a multiple of 16. Full-SoC functional verification, regenerated Platform Designer HDL, Quartus timing/resource checks, board validation and calibrated model scales remain pending. The module test does not establish full matmul correctness or 90 MHz timing.

Sources: [GELU implementation commit 52db2d1](https://github.com/j3rryhu/matmul-soc/commit/52db2d1), [integration contract](https://github.com/j3rryhu/matmul-soc/blob/600ae83/activation/rtl/INTEGRATION.md), [RTL and testbenches](https://github.com/j3rryhu/matmul-soc/tree/600ae83/activation/rtl). Local README clarifications were also reviewed; they describe this integration as a prototype requiring system validation.

## Winnie — attention softmax

Targeted `tiny_vit_21m_224`, `layers.1.blocks.0.attn`: observed scores/probabilities have shape `[16, 6, 49, 49]` over the ten local example images. Captured QKV-derived scores, probabilities, V, context and final logits; reconstructed attention outputs and model logits match the original bit-for-bit. The independent float64 softmax reference has worst probability absolute error about 1.84e-7 against PyTorch float32. The filename-sorted split uses seven calibration and three held-out images, not a labeled accuracy benchmark.

Calibration selected signed 16-bit scores with eight fractional bits, exponential cutoff 12, a 3073-entry 16-bit exponential ROM, and unsigned 16-bit probability codes normalized by 65535. The RTL uses exact iterative integer division. Score generation, scaling, attention bias, V and P @ V remain outside the fixed-point hardware boundary.

Recorded standalone ModelSim verification passed 147 rows / 8,666 outputs bit-for-bit, including row lengths 1/2/49/196, boundaries, backpressure and reset. Recorded Quartus Prime Lite 18.1 routing for Cyclone V `5CSEMA5F31C6` meets an 11.111 ns target (approximately 90 MHz): 222 ALMs, 264 registers, 10 M10Ks, zero DSPs, worst setup slack +3.188 ns and hold slack +0.129 ns. These are standalone harness results. The stall-free initiation interval is 39N cycles: about 21.23 microseconds for 49 keys at 90 MHz.

Next: define and integrate the accelerator interface, reconcile the SoC clock/SDC configuration, check full-SoC timing and validate model-level behavior. A pipelined divider or row reciprocal could improve throughput later.

Sources: [softmax commit 600ae83](https://github.com/j3rryhu/matmul-soc/commit/600ae83), [reference and fixed-point contract](https://github.com/j3rryhu/matmul-soc/blob/600ae83/softmax/README.md), [RTL verification](https://github.com/j3rryhu/matmul-soc/blob/600ae83/softmax/rtl/README.md), [Quartus results and limitations](https://github.com/j3rryhu/matmul-soc/blob/600ae83/softmax/quartus/README.md).

## Jerry — matmul main branch

Read the fetched `main` branch at [4b749ce — added address remapping and full sw tiling](https://github.com/j3rryhu/matmul-soc/commit/4b749cedf88742dc999267999cd234186eb26bf7), committed November 3, following the October 20 commit titled “Fully functioning matmul accelerator.”

- Added host address remapping so software transfers contiguous row-major matrices with rows padded to 16-byte words; hardware maps them into banked weight/input buffers and remaps output reads.
- Added tiled output placement through `TILE_CFG` (0x70), full-canvas width through `TILED_MAT_DIM` (0x80), and `use_prev_out` for accumulation across separate matmuls. The output canvas is 64 KiB at offset 0x9000.
- Added a host tiling test program with a 256x256 canvas made from four 128x128 tiles, contraction split into two chunks, a second-seed overwrite check, and unaligned column tiles on a 40-column canvas padded to pitch 48. The program includes byte-level golden comparisons and padding/spill checks; its presence alone is not a recorded passing board run.
- The committed benchmark log records 34.978 GOP/s compute and 11.527 GOP/s end to end for 2,097,152 MACs, with total 363.85 microseconds. Host verification reads are excluded from that total. A second entry records 31.351 and 10.210 GOP/s. The log does not identify these as the new full-canvas tiling tests.

Next validation issue: the tiling program documents a DMA reachability limit. A 64 KiB canvas starting at 0x9000 ends at 0x19000, beyond the configured 0x0000–0xffff DMA window and 16-bit DMA read address. The program provides `-p` PIO mode; full-canvas DMA needs address-window/interface changes or another verified transfer strategy. Capture explicit board pass logs for the tiling phases.
